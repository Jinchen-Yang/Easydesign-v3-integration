# 07 契约 — 最终筛选与候选选择

        [English](CONTRACT.md)

        **契约状态：** 概念版 `0.1`；机器 schema 刻意延后到首次实现验证完成后再冻结。

        ## 输入

        - Stage 06 规范化预测结果和原始候选溯源。
- 版本化最终 filter/ranking profile 和请求的 Top N 上限。
- 聚类、多样性和人工审核规则。

        ## 输出

        - 按 candidate 和 rule 展开的最终决策表。
- 兼顾排序和多样性的 Top N 建议。
- 包含序列、结构、指标、警告和审计链接的审核包。
- 显式人工批准状态；不产生外部下单副作用。

        ## 不变量

        - Top N 是上限，绝不要求纳入未通过候选来凑数。
- 每个排序值和排除原因都得到保留。
- 推荐、批准、下单和实验验证是不同状态。

        ## 失败状态

        - 最终 profile 无效或必需证据缺失。
- 没有候选通过；空推荐是有效结果。
- 审核包无法重建候选身份或溯源。

        失败必须写成带类型错误信息的终态 attempt 记录，不能转换成空成功。重试必须建立
        新 attempt，并引用失败 attempt。

        ## 溯源要求

        Manifest 必须记录上游 manifest 和 artifact hash、解析后配置、代码 revision、
        adapter/backend 身份和版本、适用时的模型身份、随机种子、executor profile、
        时间、警告和全部 attempt 状态。

        ## 完成门槛

        - 每个评估候选都有最终可审计处置。
- 推荐中没有失败候选，并符合多样性规则。
- 人工无需访问隐藏后端状态即可批准或拒绝。
