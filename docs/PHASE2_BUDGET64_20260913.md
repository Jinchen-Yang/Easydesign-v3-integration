## Small native summary hysteresis

The previous policy summarized whenever approximate total input reached 20,000 tokens.
With the current 60k working target / 100k hard guard, the native policy now requires
20,000 approximate tokens AND 12 effective messages, OR 22,500 approximate tokens when
headroom is tighter. These are framework trigger clauses, not new context guards. The
provider-aware threshold adjustment, retained-token budget, original trace offload,
summary prompt and callback accounting are unchanged. Exact input admission still checks
100,000 characters independently, including schemas and tool arguments. Token estimates
are not exact character measurements or provider billing totals.

Saved checkpoint inspection found no byte-identical repeated tool bodies. The largest
single delivered tool result was the complete receptor view (35,238 characters); original
research tool results were mostly focused views (largest 3,505 characters), retrieval
pages at most 5,232, and scoped result reads at most 4,277. There is no evidence here for
blindly replacing all delivered facts with another pointer layer. The summary itself
retained 6,465–8,831 characters; native completed Research rounds also retained substantial
signed reasoning, sometimes over 20k characters. Combined with a complete recent tool
transaction, this can cross the threshold again after one round. Keep the model profile
and exact scientific payloads; defer deeper compression/duplicate-fact optimization.

The minimum effective-history condition can avoid maintenance after a short history below
the high-water threshold. It does not promise fewer summaries on every future trace: a
large new transaction may still require summarization. The checkpoint's native cutoff
remains authoritative across restart. No extra memory store, pointer or alias subsystem
was added, and summaries are neither free nor unlimited.
