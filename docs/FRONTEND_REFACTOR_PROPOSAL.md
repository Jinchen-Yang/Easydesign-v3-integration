# EasyDesign 前端架构重构方案

> **目标**：将 Easy、Pro、账号门户合并为单一 SPA，解决九大痛点，提升用户体验和可维护性。  
> **约束**：后端 Python 服务保持不变，仅前端重构。  
> **日期**：2026-09-29

---

## 一、问题诊断：从九个痛点到四个根因

### 1.1 用户旅程中的痛点

| 痛点 | 场景 | 根因 |
|-----|------|-----|
| ① 产品不可见 | 访问 `/` 被甩到登录页，看不到产品 | 无访客态 |
| ② demo 死岛 | `/easy/?mode=demo` 链接指向 `127.0.0.1:13180`，无登录入口 | demo 是开发产物 |
| ③ 注册失联 | 注册后无状态通知 | 后端能力缺失 |
| ④ 登录无记忆 | 深链登录后回到门户，丢失原始目标 | 无路由层 |
| ⑤ 过期弹跳 | 会话过期立即跳转，工作丢失 | 无交互设计 |
| ⑥ 深链断裂 | 分享链接需登录，登录后回不去 | 无路由层 |
| ⑦ 语言三体 | 账号中文、Easy 中文、Pro 英文、demo 双语 | i18n 孤立 |
| ⑧ 整页刷新 | 跨面切换全靠 `location.href` | 无路由层 |
| ⑨ 404 裸 JSON | 错误页返回 JSON，无 HTML | 服务端小问题 |

### 1.2 根因分析

```
根因 A：无统一路由/导航层
  └─► 痛点 ④⑥⑦⑧

根因 B：demo 是开发产物
  └─► 痛点 ②⑦

根因 C：会话生命周期无交互设计
  └─► 痛点 ④⑤

根因 D：i18n 只在 demo 实现
  └─► 痛点 ⑦
```

**关键判断**：这九个痛点不是九个独立 bug，而是四个根因的外显。

### 2.2 关键技术约束

| 约束 | 现状 | 影响 |
|-----|------|------|
| **后端路由** | 只支持 `/`、`/easy/`、`/account/`、`/api/*` | 不能用 Browser History 路由 |

| **技术栈** | React 19 + Vite 6 + TS 5.7 | 保持不变 |

✅ **可复用**：
- Adapter 模式：`DemoAdapter`、`EasyProductAdapter`、`LiveWorkbenchAdapter` 已经实现数据源抽象
- i18n 基础设施：`easy/i18n.ts` 可扩展
- 账号 API 客户端：`account-client.ts` 可直接复用
- 草稿 API：后端已有带版本的草稿接口
- 3D 查看器：`MolecularViewer` 可直接迁移

❌ **需新建**：
- 统一路由层
- 会话状态机
- 草稿恢复模块
- 语言切换基础设施
- 访客态壳

### 3.2 核心模块设计（每个模块回答三问）

#### 模块 1：会话状态机 (SessionStateMachine)

**解决什么问题？**  
管理四种会话态（访客 / 已登录 / 过期待恢复 / 网络异常），避免痛点⑤的无预警弹跳。

**依赖谁？**  
`account-client.ts` 的 `AccountSession` 类型和 `accountApi` 函数。

**被谁调用？**  
应用壳和所有需要鉴权的视图组件。

```typescript
type SessionState =
  | { kind: 'guest' }
  | { kind: 'authenticated'; session: AccountSession; scope: AccountScope }
  | { kind: 'expired'; previousSession: AccountSession; recoveryData: RecoveryData }
  | { kind: 'checking' }
  | { kind: 'network-error'; retry: () => void };

// 状态转移
guest --[登录成功]--> authenticated
authenticated --[401]--> expired
expired --[重新登录]--> authenticated
expired --[换账号]--> guest (清除旧数据)
```

#### 模块 2：草稿恢复模块 (DraftRecovery)

**解决什么问题？**  
会话过期后保留未提交的输入、文件选择、审核备注，避免痛点⑤的工作丢失。

**依赖谁？**  
会话状态机（订阅 `expired` 事件）、后端草稿 API（`draftsApi`）。

**被谁调用？**  
项目创建表单、Gate 审核组件。

```typescript
interface DraftRecovery {
  // 分层保存
  saveLocal(key: string, data: unknown): void;        // 前端 sessionStorage
  saveRemote(draft: ProjectDraft): Promise<void>;     // 后端草稿 API
  
  // 恢复策略
  recover(key: string): {
    hasLocal: boolean;
    hasRemote: boolean;
    data: unknown;
    savedAt: number;
  };
}
```

#### 模块 3：Hash Router 导航

**解决什么问题？**  
在不改后端路由的前提下实现 SPA，解决痛点④⑥⑧。

**依赖谁？**  
React Router v6 Hash Router。

**被谁调用？**  
应用壳和所有视图切换逻辑。

```typescript
// 路由表
/ → 根路由，重定向到 /#/
/#/ → 访客看到演示壳，已登录看到项目列表
/#/projects → 项目列表
/#/projects/:id?scope=:scopeId&view=easy → Easy Live
/#/projects/:id?scope=:scopeId&view=pro → Pro
/#/account → 账号与团队
/#/demo → 显式演示模式

// 旧链接兼容（应用启动时解析并重定向）
/easy/?scope=x&project=y → /#/projects/y?scope=x&view=easy
/?scope=x&project=y → /#/projects/y?scope=x&view=pro
/account/ → /#/account
```

#### 模块 4：语言权威 (I18nProvider)

**解决什么问题？**  
统一管理全应用语言，解决痛点⑦的语言三体。

**依赖谁？**  
`i18next` + `react-i18next`。

**被谁调用？**  
应用壳和所有需要翻译的组件。

```typescript
// 词典结构
resources/
├── zh/
│   ├── common.json       # 导航、按钮、表单
```

## 四、分阶段实施路线

### 阶段 0：准备（1-2 天）

**目标**：建立共享基础设施，不影响现有页面。

1. 创建 `web/app/` 作为新应用根目录
2. 搭建 Vite 配置，支持多入口（兼容期）
3. 迁移 `account-client.ts` 到 `web/app/shared/`
4. 实现会话状态机（单元测试覆盖）

### 阶段 1：止血（3-5 天）

**目标**：解决痛点④⑤，立即生效。

**改动点**：
- `account-client.ts` 中的 `scopedTransport`：401 时不再 `location.replace()`，而是发出事件
- 新建 401 恢复遮罩组件（覆盖在当前页面上）
- 实现 `?next=` 机制（纯前端，localStorage 暂存）
- 实现滑动续期（**唯一后端改动**：`accounts.py` 的 `authenticate()` 更新 `expires_at`）

**验收标准**：
- 会话过期后弹出重新登录遮罩，输入保留
- 登录成功后回到原页面
- 会话在活跃期间自动续期

### 阶段 2：统一壳（1 周）

**目标**：建立单一应用壳，Easy 和 Pro 作为视图挂入。

**改动点**：
- 创建 `web/app/src/App.tsx`：应用壳 + Hash Router
- 创建 `web/app/src/shell/`：导航、语言切换、会话恢复
- 迁移 Easy Live 到 `web/app/src/views/easy/`
- 迁移 Pro 到 `web/app/src/views/pro/`
- 迁移账号门户到 `web/app/src/views/account/`
- 实现 i18n Provider（复用 `easy/i18n.ts` 的词典）

**验收标准**：
- Easy/Pro/账号之间切换不整页刷新
- 语言切换实时生效，状态持久化
- 旧链接自动重定向到新路由

### 阶段 3：访客态（1 周）

**目标**：首页可见，动作边界鉴权，解决痛点①②。

**改动点**：
- 修改 `/#/` 路由：立即渲染工作台壳（访客看到演示，已登录看到项目列表）
- 将 demo 模式从开发产物转为正式访客视图
- 修复 demo 中的死链（`127.0.0.1:13180` 改为相对路径）
- 添加登录 CTA（"登录使用完整功能"）
- 在动作边界（提交设计、批准 Gate）显式要求登录

**验收标准**：
- 访问 `/` 立即看到产品界面
- 访客可完整体验演示流程
- 试图提交真实任务时弹出登录提示
- demo 内的链接可正常跳转

### 阶段 4：发布与回归（3-5 天）

**目标**：部署新版本，保留旧版本回滚能力。

**改动点**：
- 构建新应用到 `runtime/ui-app-{commit}/`（不覆盖旧的 `ui-{commit}`）
- 后端 `server.py` 增加路由：`/` 和 `/app/` 指向新应用
- 保留 `/easy/` 和旧 Workbench 路由（兼容期 2 周）
- 全流程回归测试：登录、项目创建、会话过期恢复、语言切换、跨浏览器

**验收标准**：
- Playwright e2e 测试全部通过
- 10 个交接账号可正常使用
- 旧链接自动重定向到新应用
- 如有问题可立即回滚到旧版本

### 阶段 5：清理（1-2 天）

**目标**：移除旧代码，统一构建流程。

**改动点**：
- 删除 `web/easy/` 和 `web/workbench/`
- 统一 Playwright 配置到 `web/app/`
- 更新 CI/CD 脚本

## 五、技术决策理由

### 5.1 为什么用 Hash Router 而不是 Browser History？

| 方案 | 优点 | 缺点 | 决策 |
|-----|------|------|------|
| Browser History | URL 美观 | 需要后端支持通配路由 | ❌ 后端不改 |
| Hash Router | 无需后端改动 | URL 有 `#` | ✅ 采用 |

**类比**：Hash Router 像客户端路由表，浏览器看到的是同一个文档（`/`），但通过 `#` 后的内容在前端内部导航。

### 5.2 为什么用 TanStack Query 而不是手动 fetch？

| 需求 | 手动 fetch | TanStack Query | 决策 |
|-----|-----------|----------------|------|
| 请求去重 | 需手写 | 内置 | ✅ |
| 后台刷新 | 需手写 | 内置 | ✅ |
| 缓存失效 | 需手写 | 内置 | ✅ |
| 乐观更新 | 需手写 | 内置 | ✅ |

**类比**：TanStack Query 像 Git 一样管理服务器数据——本地缓存、远程同步、冲突解决。

### 5.3 为什么不用 Next.js？

| Next.js 特性 | 是否需要 | 理由 |
|-------------|---------|------|
| SSR | ❌ | 无 SEO 需求，纯 SPA |
| API Routes | ❌ | 后端已有 Python 服务 |
| File-based Routing | ❌ | Hash Router 够用 |

**决策**：保持 Vite + React，避免过度工程。

### 5.4 为什么不微前端？

| 微前端优点 | 适用场景 | EasyDesign | 决策 |
|----------|---------|-----------|------|
| 独立部署 | 多团队协作 | 单团队 | ❌ |
| 技术栈隔离 | 遗留系统集成 | 统一 React | ❌ |

**决策**：单体 SPA 足够，微前端增加复杂度无收益。

## 九、结论

这份方案通过四个阶段逐步解决九大痛点，核心是建立统一的应用壳、会话状态机和 Hash Router，而不是推倒重来。每个阶段都有清晰的验收标准和回滚方案，最小化风险。

**关键优势**：
1. **渐进式**：阶段 1 即可见效，不是"大爆炸"式重构
2. **可回滚**：每阶段保留旧版本，出问题立即回退
3. **零后端改动**：除了滑动续期（可选），后端完全不动
4. **用户无感**：旧链接自动重定向，无需用户适应

**下一步**：确认方案后，进入阶段 0 准备期。
