# 02 — Demo Flow Spec

## 核心原则

Demo 使用确定性状态机，不等待真实 scientific backend。

进入每一阶段后：
- 依次播放 2–4 个 research/tool events；
- 更新左栏 subtasks；
- 更新右栏 context；
- 到决策点暂停；
- 用户点 Approve 后进入下一阶段。

提供 `Replay demo` 和 `Reset`。

## Demo target

**UI Demo Fixture: Lysozyme VHH**

建议结构：
- PDB: 1MEL
- target: hen egg-white lysozyme
- target chain: C（若实际解析不同，以结构文件为准）
- known VHH chain for final visualization: A
- UniProt shown in UI: P00698

任何 mock metric、mock residue set、mock candidate score 都必须标记为 demo/simulated。

## Stage 1 — Goal

User:
`Design a VHH binder against hen egg-white lysozyme and prioritize a compact accessible epitope.`

EasyDesign:
- restates goal in one short paragraph;
- identifies VHH as binder;
- sets demo scope;
- automatically moves to Target.

Right panel:
- Goal card
- target: Lysozyme
- binder: VHH
- objective: binding demo
- mode: UI Demo Fixture

## Stage 2 — Target

Subtasks:
1. Parse target request
2. Load reference structure
3. Resolve target chain
4. Prepare structure context

Conversation events:
- Target Intelligence started
- Structure metadata loaded
- Reference structure ready

Right:
- show target-only structure;
- show PDB 1MEL / UniProt P00698;
- show chain selector;
- show short sequence strip or placeholder.

Decision:
`Approve target`

## Stage 3 — Site

Subtasks:
1. Inspect target surface
2. Generate A/B/C site candidates
3. Compare demo accessibility
4. Select recommended site

Create three visually separated mock sites:
- Site A
- Site B — recommended
- Site C

The exact residue sets are UI fixtures, not scientific claims.

Right:
- viewer with site overlays;
- three small site tabs;
- Site B selected;
- 3 concise metrics per site.

Decision:
`Compare` / `Edit` / `Approve Site B`

## Stage 4 — Design

Subtasks:
1. Confirm approved site
2. Select VHH scaffold
3. Define two pilot arms
4. Set small candidate budget

Design arms:
- Focused hotspot
- Broader interface

Pilot budget:
- 4 + 4 = 8

Right:
- visual design summary
- scaffold card
- arms
- budget
- no raw YAML unless details expanded.

Decision:
`Approve design`

## Stage 5 — Pilot

Simulate exactly 8 candidates.

Events:
- generation started
- 8 sequences generated
- structure checks complete
- 6 pass / 2 fail
- recommended to promote

Right:
- 8 candidate chips/cards
- compact plot or pass summary
- one selected candidate structure
- 4 mock metrics

Decision:
`Revise` / `Promote 6 candidates`

## Stage 6 — Scale

Simulate exactly 24 candidates.

Do not require approval before every fake batch.

Show:
- 3 batches × 8
- short animated progress
- 18 pass
- 6 filtered

Right:
- progress
- candidate count
- pass-rate
- small distribution visualization

Auto-transition to Candidates after completion, or show `Review candidates`.

## Stage 7 — Candidates

Show 6 finalists.

Use the known 1MEL VHH–lysozyme complex as the visual ground-truth-style placeholder when helpful.
Do not claim these are actually generated by EasyDesign.

Each card:
- Candidate ID
- short sequence preview
- 3–4 mock metrics
- star / shortlist action

Final decision:
`Finalize panel`

On finalize:
- show completion message
- keep entire workbench browsable
- enable `Replay demo`.

## Demo timing

Default:
- each event 350–700 ms
- a stage should not take more than ~3 seconds before a decision
- Scale full animation <= 4 seconds
- allow `Skip animation`

The demo should feel active but not fake-slow.
