# v3 多用户与团队产品契约

状态：2026-09-27T12:15:50Z 本地实现完成，多用户定向与浏览器回归通过；
整体集成门仍有已复现的基线阻塞，详见 `MULTIUSER_ACCEPTANCE.md`。

本契约扩展 v3 Product API 与 Easy UI 的身份、协作和资源管理能力，不改变
`V3_SCIENTIFIC_DECISION_CONTRACT.md` 的五个 Gate、科学事实、manifest/checksum 或恢复语义。

## 已确认的产品规则

1. 用户自行注册后进入待审核状态；系统管理员批准后才能使用科研工作区。
2. 个人项目默认私有。创建时显式选择团队，才建立团队共享项目。
3. 团队成员可查看和协作编辑团队项目；团队管理员负责科学 Gate 批准及计算启动。
4. 系统管理员负责账户、团队、配额和审计，可以只读查看全站项目与结果，访问必须审计；
   系统管理员身份本身不授予他人项目的修改、计算启动或科研审批权。
5. 个人与团队拥有明确的数据归属和独立存储范围；模型以只读资产共享，GPU 使用共享池。
6. 计算同时受发起人的个人额度和所属团队额度约束；记录实际操作人，不把资源归属当作人类审批。
7. 加入团队不会自动公开既有个人项目。退出或被移除后，新请求立即失去相应团队权限。

## 比赛额度与长期产品

系统用于本次蛋白质设计比赛，并在比赛后作为长期产品继续完善。比赛额度属于可配置的
产品政策，不能把这次比赛的数值写成不可调整的科学算法限制。

- 本次比赛的个人额度预设为累计 30 个最终设计；Pilot 前置筛选不另扣这份最终设计额度。
- 当前比赛流程沿用 Pilot 预算 30、Scale 预算 30 的配置；七个策略均分 Pilot 时实际为
  28 个候选。阶段预算、个人总额度及并发/GPU 等资源上限须有明确、可调整的管理入口。
- 个人累计最终设计额度与 `max_candidates_per_job` 的单次执行上限含义不同，界面和账本
  必须分别说明；额度计量不能靠前端显示数字实现。
- 配置变更须审计，且不得改写已冻结的科学方案、审批历史和既有结果。已批准方案超出新的
  可用额度时明确阻止执行或重新取得批准，不静默缩减方案。

用户已批准新建独立集成 worktree，本轮合并来源锁定为
`592e1e5646dd6e8d512fe0706230f0d2d4144fb3`；比赛政策配置与多用户接入在集成后联合验收。

## 身份与授权不变量

- 用户身份由服务端会话确定；浏览器提交的 user/owner/actor/role 字段不能授予权限。
- 未审核、停用账号和过期/撤销会话不得调用科研接口。
- 所有项目、任务、上传、请求、事件、候选、artifact、下载和导出均经过服务端授权。
- 不能靠页面隐藏、`surface=easy`、不可猜测编号或前端过滤实现用户隔离。
- 团队成员不能通过直接 HTTP 请求批准 Gate、启动/恢复计算或借用其他人的额度。
- 修改密码、停用账户、变更成员关系等操作不改写已有科学证据或审批历史。
- 资源检查必须在实际工作执行路径生效；只有界面中的配额数字不算资源隔离。
- 同一请求的重试保持幂等；跨用户、跨团队复用请求编号不得串用结果或绕过权限。
- 冻结科学方案、模型判断、系统管理员权限均不替代当前合法科研审批人的明确动作。

- 开发环境和测试数据只属于本开发目录；生产目录的未提交内容不作为同步或覆盖目标。
- 对方后续提交先记录 commit 和改动范围，再在独立集成工作树合入、解决冲突并验证。
- 最终切换生产服务前仍需完成合并与部署审批，不能以开发任务自动授权生产切换。

## 验收要求

至少覆盖：两个个人用户、两个团队、团队管理员、普通成员和系统管理员。

1. 注册 → 审核 → 登录 → 修改密码/退出 → 会话撤销。
2. 个人项目与团队项目在列表、详情、事件、请求、下载和 artifact 中的读取/写入权限。
3. 团队邀请/接受、移除成员及权限即时生效；并发或重复操作的幂等性。
4. 成员协作编辑与管理员科学审批的区别；伪造 actor、绕过前端和跨用户编号攻击均失败。
5. 个人/团队配额的并发竞争、拒绝/等待、恢复、释放与审计，不终止无关科学进程。
6. 完整 Product API → worker → native Runtime → Gates → results → 同团队访问链路。
7. 账号角色、团队共享和关键异常状态的真实浏览器验收。
