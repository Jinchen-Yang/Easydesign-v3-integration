### 遇到的问题

- TNP 上游 `setup.py` 不声明实际依赖：缺 PDBFixer/OpenMM 和 scikit-learn；现代
  setuptools 又移除了旧代码需要的 `pkg_resources`。
- TNP 官方安装链接的 salilab DSSP 3.0.0 被求解到 Boost 1.91，但可执行文件仍请求
  `libboost_thread.so.1.73.0`，无法启动。
- TNP liability 文件扩展名是 `.json`，内容实际为 CSV；真实记录包含
  `111A/111B/111C`，只保留整数会丢失 IMGT insertion code。
- 仅凭 TNP result JSON 存在无法证明 resume 输入、backend 和完整收集相同。
- Proteindigger1 根分区满载使默认 `/tmp` 的 wheel/pytest smoke 报
  `No space left on device`。

### 解决办法

- 固定 Python 3.10、ANARCI 2024.05.21、Biopython 1.77、ImmuneBuilder 1.2、
  OpenMM 8.5.2、PDBFixer 1.9、scikit-learn 1.7.2、Torch 2.13 和 setuptools 80.9；
  doctor 同时检查 Conda package 与 Python distribution identity。
- 用真实可运行的 conda-forge DSSP 4.6.1 / Boost 1.90 代替失效组合；adapter 显式绑定
  prefix PATH/LD_LIBRARY_PATH、关闭 user-site 和 GPU 可见性。
- 按 CSV 内容契约解析 liability，并新增原始 `numbering_label` 保存 insertion code。
- TNP 成功 attempt 只有在 immutable receipt、input/result SHA-256、candidate IDs 和
  backend identity 全部匹配时才复用。
- 本任务的 Conda/pip/pytest/wheel 临时目录全部移到 `/root/autodl-tmp`；没有清理或
  中断其他用户任务。
